# API Contracts

GET /api/health and /api/skills are public. POST /api/demo creates isolated fictional records. /api/auth/register, login, logout manage local sessions. /api/me returns a safe identity. /api/classrooms supports list/create; POST /api/classrooms/enroll takes a code. /api/questions previews generation. /api/assignments supports list/publish. /api/submissions creates one record per student/assignment. Submission routes expose GET, PATCH transcription, POST confirm/image/reviews, and GET image. Classroom routes expose submissions, analytics, and cursor-based events. Mutations require an Origin matching the request origin. Validation is in packages/contracts; contracts differ from representative target endpoints where documented.

## Durable OCR routes

Owner-only POST `/api/submissions/:id/process` requires positive `version` and UUID `idempotencyKey`; returns 202 with job id/status/idempotent. Missing image: 400; stale version/locked state/key reuse with conflicting version: 409; rolling-day quota: 429; provider absent: 503. GET submission includes provider availability and latest job status/original structured output for its existing authorized student/teacher audience. POST `/manual-entry` with current version cancels active work or exits review/failure without erasing prior transcription. The inference service is never exposed through an unauthenticated browser endpoint. See [[OCR-Pipeline]].

GET /api/assignments returns an explicit StudentQuestion display contract to students: id, skillId, difficulty, prompt, expression, explanation, figure, answerForm, answerUnit and reasoningDomain (optional fields omitted when absent). It omits reference, alternativePaths, parameters, seed, template metadata and unrecognized internal fields. Authorized teachers retain the stored snapshot; server grading always reads that immutable snapshot. The frontend assignment view uses the same narrowed type.

`GET /api/classrooms/:id/mastery?studentId=...` returns classroom-scoped current model estimates, evidence counts, status and explicit provisional parameters. Students may request themselves only; the classroom owner may request an enrolled student. Anonymous requests fail 401; foreign scopes/peers fail 404. Submission inspection includes the same authorized student's classroom mastery. Review POST atomically replaces/retracts one evidence item and recomputes current estimates; append-only review history and original evaluation remain intact. Repeated review requests may append review-history records but do not multiply mastery observations.

`POST /api/submissions/:id/remediation` accepts only `{reviewId: UUID}` and requires classroom ownership, finalized source work, the latest needs_practice review and an enrolled target student. It returns `{id, idempotent}` (201 on publication, 200 for an existing follow-up). Missing/unsuitable review, stale review and unenrolled target return 409. One transaction saves the generated assignment, recommendation provenance and two publication events. The assignment is listed only to its target student and classroom owner; a peer who guesses its ID cannot create a submission. Student question projections continue omitting answers and generation parameters. Submission inspection exposes the linked practice title/reason and eligible review ID to its authorized viewer.
